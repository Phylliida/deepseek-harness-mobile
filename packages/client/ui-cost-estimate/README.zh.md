# @deepseek-ai/dsh-client-ui-cost-estimate

[English](README.md) | 中文

面向 composer 停靠区的会话费用估算：stats 行上方的一条同族信息行，用用户可配置的费率表为整个会话的持久 token 日志计价。两半同处一个包——Host 入口持有设置段，浏览器入口渲染估算值。

## 显示内容

该行读取持久的 `tokenUsage` 投影（`uncachedInputTokens`、`cacheReadTokens`、`cacheWriteTokens`、`outputTokens`），将各桶乘以配置的每百万 token 费率。它以 `order: -1` 注册在 `conversation.composer.dock` 上，位于 stats 行的 `0` 之前，因此估算领跑 composer 下方的汇总带。悬停显示分桶明细；两种语言文案均随包发布。会话尚无计费 token 时该行不渲染；该数值只是参考估算，不是账单记录——计费以提供商自己的账户为准。

该数值是持久投影与持久设置段的纯函数，因此翻页、压缩、重连都不需要任何驻留记账：不存在可能失同步的跨插件可变状态。

该行还标出估算占所配置每周预算的比例——`预估费用 ~$5.10 (4.3%)`——悬停明细中另附预算句。`weeklyBudgetUsd` 为 `0` 时省略比例。

## 费率与预算配置

设置存于 Host 用户设置文档的 `ui-cost-estimate` 命名空间：`rates` 字段含四个非负的美元每百万 token 价格，`weeklyBudgetUsd` 字段是估算比例所参照的每周预算（默认 `$120`；`0` 隐藏比例）。费率默认值为 Moonshot 公布的 Kimi K3 标准 API 费率——无缓存输入 `$3`、缓存读取 `$0.30`、缓存写入 `$3`(K3 的缓存写入按普通输入计费)、输出 `$15`——文档中省略的单个值回退到这些默认值。在用户设置文档中编辑该段即可为其他提供商计价或重新设定预算；浏览器作用域通过设置失效事件实时捕获变更，行会无需刷新即重算。

```yaml
ui-cost-estimate:
  rates: { input: 3, cacheRead: 0.3, cacheWrite: 3, output: 15 }
  weeklyBudgetUsd: 120
```

没有设置提供方的部署保持默认值：命名空间缺失期间，浏览器作用域回退到 schema 默认值。

## 模型体验

无：composer 停靠区的估算只按费率表渲染持久 token 总量；这里的任何内容都不会进入模型请求。

#### KV Cache 影响

无。

## 已知限制与待办工作

- **无界面内费率编辑器**——目前只能在用户设置文档中编辑该段；带四个数字输入框的 Settings 页面行暂缓，有需求再做。
- **整个部署共用一张费率表**——不同定价模型的会话共用同一张表；按适配器路由费率需要把模型身份带入 fold，而持久投影有意不把模型身份带入 UI 运算。
- **估算裁剪的是显示精度而非运算**——低于一美分的费用显示四位小数，非零但不足预算千分之一的比例显示 `<0.1%`；精确数值可通过悬停明细中的 token 计数与配置费率获得。
