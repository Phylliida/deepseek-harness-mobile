# @deepseek-ai/dsh-user-model-driver

[English](README.md) | 中文

[用户模型伴随](../user-model/README.md)的驾驭驱动器：会话上启用用户模型后，每当确切的存活智能体停滞，它代替用户作答——直到模型自行宣布目标完成、达到回复上限或发生故障，随即持久停用，由人类接管。

## 组合

```yaml
- id: user-model
  name: '@deepseek-ai/dsh-user-model'

- id: user-model-driver
  name: '@deepseek-ai/dsh-user-model-driver'
```

`maxReplies`（默认 20）限制每次启用的回复条数；`maxTokens`（默认 4096）限制每次生成的预算。两者都必须是正整数，并在 apply 时校验。

## 驾驭契约

仅当满足以下全部条件时，驱动器才认为智能体可驾驭：fiber 处于 ACTIVE、该 `Agent` 生命周期仍是注册的那一个、智能体 `idle` 且收件箱为空、没有正在运行或停止的所属任务、且日志折叠出启用选择。驱动器在 `agent/status` 转为 idle、任务集合变化、以及 `user-model/armed` 事件时被唤醒——后者经 microtask 调度，因为 `Session.append` 拒绝在事件发布期间重入。生成前或生成期间到来的人类输入会使在途回复失效：驱动器在等待返回后重新检查就绪条件，丢弃该回复而不是打断人类。

一次回复是一次 `callUserModel` 生成：系统提示词为人设，消息为角色翻转的转录；所得文本以携带 `user-model` 来源的 `user/message` 进入会话。以 `<task-complete/>` 结尾的回复在送达前置文本后以 `complete` 原因停用。问题与审批请求不由驱动器处理——apiproxy 的转发在内联路径上回答它们。

## 停用是持久的

每次退出启用状态都会追加 `user-model/disarmed`：`user`（经 RPC 的显式停用或重新启用）、`complete`（哨兵）、`turn-failed`（智能体最后一个回合中止或出错）、`generation-failed`（适配器故障、输出不可解析或后续发送无法提交）、`replies-exhausted`（达到每次启用上限）。在驾驭已调度或在途时请求的停用会被记录下来，由同一次运行提交。若停用追加本身失败，驱动器失败即关闭——不再回复——并记录日志。

## 生命周期与持久性

插件卸载会把每个存活状态标记为停止、中止在途生成，并等待运行与智能体静默；卸载期间的持久化失败不会留下重新调度的工作。在已启用的会话上加载是安全的：启用折叠由回放派生，驱动器只是从下一个空闲检查点开始兑现它。

## 模型体验

### 驾驭回复

#### 模型看到的内容

域包的人设提示词与角色翻转转录，与 [`dsh-user-model` 的模型体验](../user-model/README.md#model-experience)所述完全一致；驱动器不添加自己的提示内容。

#### Token 影响

每次停滞产生一次辅助生成，受 `maxTokens`（默认 4096）约束；每次启用的回复条数受 `maxReplies`（默认 20）约束。

#### KV Cache 影响

每条回复向会话日志追加一条 user 角色消息，智能体的下一次请求因此增加该回复；辅助调用本身走启用路由自己的缓存情形。

## 已知限制与暂缓事项

- **回复上限而非资源预算** —— token、费用与时间策略相互独立；驱动器只计回复条数。
- **无异常自动重试** —— 生成失败即停用而非重试；是否重新启用由人类决定。
- **只响应停滞** —— 驱动器只在停滞时作答；不会抢占已排队的人类输入，也不在回合中途介入。
