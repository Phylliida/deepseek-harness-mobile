# @deepseek-ai/dsh-memory-log

[English](README.md) | 中文

日志记忆提供方（`ctx.memory`）：以 harness 服务形式实现的 [OptMem](https://github.com/VictorTaelin/OptMem) 设计，与上游存储逐字节兼容。一个定长、仅追加的 `LOG.txt` 保存每条记忆；`TREE/` 下的二叉摘要树是可重建的缓存，由 agent（智能体）自己通过 nap 应答逐块压缩。细节随年龄衰减：wake 把近期记忆原样渲染，把远古记忆渲染成单行摘要，行数预算可配置。存储目录在加载时创建——把 `directory` 指向一个存储就是打开该身份的明确动作。

两个路由命令包裹这段对话，让一个 agent 为每个项目各存一份记忆：`projects` 列出 `projectsRoot` 的直接子目录（标记哪个已有存储、哪个是当前激活），`use <name>` 把激活存储切到该目录内的 `projectsDir`（`use global` 切回全局）。首次选择时会实际创建该项目的存储。

## 命令对话

`src/engine.ts` 是 `MemoryStore` 之上的 OptMem 命令对话，逐命令移植自参考实现 `memo` CLI：`wake [part [T]]`、`note "<line>"`、`nap [lo-hi "<line>"]`、`recall <regex>`、`zoom <lo-hi>`、`forget <lo-hi>`、`import <file>`。返回的文本就是 seam 的约定，包括指明下一个命令的 `Run:` 指令，agent 会将其逐字发回。命令词按单双引号切分；双引号内 `\"` 与 `\\` 转义，单引号内没有转义。`import` 批量追加 `YYYY-MM-DD <text>` 行，仅用于引导导入：日期必须真实且不递减，文件必须是 UTF-8 文本。两个上游命令被有意略去：`init`（提供方在加载时依据 Config 创建存储）与 `config`（cordis.yml 拥有这些尺寸；存储级覆盖会绕过部署）。

上游以退出码 1 加 stderr 报告失败之处，本移植抛出 `MemoryError`；唯一例外是被阻塞的 wake，其文本正是 agent 必须读到的指令，因此正常返回。`nap` 的结果是回复文本 `<block> saved.`、`<block> is already settled.`、`<block> was settled or forgotten meanwhile.` 和 `Nothing left to compress.`。

## 磁盘布局

| 路径 | 内容 |
|---|---|
| `LOG.txt` | 每条记忆一条 320 字节记录：`#i YYYY-MM-DD text`，空格补齐加换行。仅追加，从不编辑。 |
| `TREE/<n>` | 每个大小为 `n` 的块摘要一条 288 字节记录。每个层级文件都是稠密前缀：其长度精确说明该层级推进到哪里。 |
| `LOG.txt.lock` | 跨进程写入互斥锁：来自 `dsh-atomic-write` 的 `wx` 创建式同级文件，串行化每次变更，释放时删除。 |

记录定长，因此位置即身份：记忆 `i` 位于字节偏移 `i * 320`，块 `[k*n, (k+1)*n)` 位于 `TREE/<n>` 的 `k * 288`。补齐消耗磁盘，换来 O(1) 寻址且无需维护索引。所有操作都是单个异步 seam 方法之后的同步文件 I/O：每渲染一行一次 `read`，从不全扫。

## 块数学

块是一段对齐的二次幂记忆区间，打印时两端均为闭区间（`16-31`）。`cover(T, wakeLines)` 对 `[0, T)` 做铺砌，一个块保持完整当且仅当其大小不超过 `alpha` 乘以其年龄——细节随年龄衰减，因此近期记忆保持原文，远古记忆折叠为单行。如果日志未压缩就能放进预算，则完全不压缩；剩余预算花在拆分最新的块上，那里的细节最有价值。不超过 `RAW_MAX`（16）条记忆的块直接从原始日志压缩；更大的块由其两半的摘要压缩。块严格按序构建，最小的优先。

## 崩溃修复与加锁

每次变更都会先持有 `LOG.txt.lock` 写入锁，截断崩溃留下的尾部残缺记录（它从未被确认），追加，并在确认前 `fsync`。解码出替换字符的摘要会让读取以指明 forget 修复的 `MemoryError` 失败；扫描发现 `LOG.txt` 未按记录对齐时会明确报错，而不是猜测记录边界。两秒内拿不到锁的写入方会失败；被杀死进程留下的陈旧 `LOG.txt.lock` 在被手工删除前会一直阻塞写入方。该锁刻意不用上游的 `.lock` 文件：flock 与锁文件无法互斥，名字相撞反而会让任何追加在接触过 Python 工具的存储上死锁——两个实现共享一个存储只能顺序进行。

## 配置

这些大小都是读取与传输预算，绝不是存储：修改任一值都不会重新计算或改动已记录的记忆。

| 键 | 默认值 | 语义 |
|---|---|---|
| `directory` | `$DSH_HOME` 下的 `memory/`（否则 `~/.dsh`） | 全局记忆的存储目录；前导 `~` 会展开。加载时创建。 |
| `projectsRoot` | 进程工作目录 | 其直接子目录被视为 `projects`/`use` 可用的项目；前导 `~` 会展开。显式配置但不存在的根在加载时失败。 |
| `projectsDir` | `.memory` | 在被选中项目内创建的存储目录；必须为单一目录名、不含分隔符，否则加载失败。 |
| `wakeLines` | `96` | 一次 wake 渲染的行数（96 ≈ 8k token 的稠密文本）。 |
| `entryChars` | `280` | 一条记忆或摘要行的最大 UTF-8 字节数；上限 280，因为一条记录必须同时装进两种记录格式。 |
| `partChars` | `20000` | 单个输出部分的最大 UTF-8 字节数（harness 截断余量）。 |
| `partLines` | `500` | 单个输出部分的最大行数。 |

## OptMem 归属

本设计——定长仅追加日志、对齐二次幂摘要树、agent 参与的压缩——来自 [OptMem](https://github.com/VictorTaelin/OptMem)。上游仓库没有 LICENSE，因此本包是净室 TypeScript 重实现：只复现已发表的算法与格式，不复用其代码。记录宽度与上限沿用上流的实测值（320/288 字节、280 字节条目、`RAW_MAX` 16）。

## 模型体验

通过 `dsh-tool-memory` 间接影响；该 Consumer 把提供方的对话文本逐字传给模型，作为 `memory` 工具的结果。

#### KV Cache 影响

不会直接导致 KV Cache 失效；请求前缀与历史的全部变更由具名 Consumer 负责。存储自身的旋钮是读取预算，修改它们只改变之后的渲染，不会触碰已记录的记忆。

## 已知限制与暂缓事项

- **recall 仅支持正则**：`recall` 是对原始日志行做不区分大小写的正则匹配；没有语义或嵌入向量搜索。
- **作用域选择是进程级的**：`use <name>` 切换的是这个提供方实例上的激活存储，同一组合内的所有会话共享这一选择：并行会话若分别选择不同存储会互相竞争该内存字段，应用重启也会把选择重置回全局记忆（目标是单用户部署）。
- **同级写入锁**：跨进程互斥最多等待两秒，随后报错；被杀死进程留下的陈旧 `LOG.txt.lock` 在被手工删除前会一直阻塞写入方，且通过上游 Python 工具的并发写入方不被排除（flock 与锁文件不相互作用）。
- **无脱敏、无 GC**：`LOG.txt` 仅追加且从不编辑，因此记入的机密或过时事实会一直留在磁盘上，直到存储目录被删除；压缩封顶的是读取预算，不是存储。
