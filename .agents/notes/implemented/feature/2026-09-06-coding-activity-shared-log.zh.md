# Agent Note: 编码活动改为共享交互日志——打点相邻即桥接汇总

Status: implemented

[English](2026-09-06-coding-activity-shared-log.md) | 中文

## Problem

[侧边栏编码时长追踪器](2026-08-23-coding-time-tracker.md)度量的是用户*声明*的内容——按一下“开始编码”，由“停止编码”或[无操作自动停止](2026-09-01-coding-idle-auto-stop.md)结束——并把历史保存在浏览器 localStorage 里，因此桌面与手机从构造上就互不一致。需求：不再度量声明，改为测量在场。记录每一次交互（点按、点击、指针移动、按键、滚动）；把相邻间隔不到两分钟的两枚打点连成一段区间；对区间求和——孤立的打点不计时，但必须能成为下一枚打点的锚点。而且这份日志必须是跨全部设备的共享记录，而不是按浏览器分开的状态，这样手机上的清晨和桌面上的午后才能加在同一份历史里。

## Decision

**打点折叠为桥接合并的区间，折叠由服务器一方完成。** 每个浏览器把输入打点写进 `ctx.codingActivity`（`dsh-coding-activity`，新包位于 `packages/coding/`）：一份只追加的文档，持久化在 `$DSH_HOME/coding-activity.json`，存放的是规范化的*区间*——相邻间隔严格小于 `CODING_ACTIVITY_BRIDGE_MS`（120 000 毫秒——格式常量而非可调项，否则每个读者拿出的折叠语义都会不同）的最长打点串。合并是对排序后区间的同一条结合且可交换的运算，两台设备并发写入的结果与到达顺序无关；追加方在跨进程写锁内先重读文档再折叠，因此两个 dsh 进程不会互相覆盖。窗口内没有邻点的打点时间以零长区间存活：它本身不计时，但锚定未来的桥接——正是用户给出的例子（第 1、2、5、6、7、10、11 分钟的打点合计 1 + 2 + 1 分钟）。规范化把存储压到每次工作突发一条区间，而不是每秒输入一条记录。

**线上是一对不加权限限制的 RPC，外加一个原样转发的变更事件。** `coding.read` / `coding.write`（`dsh-host-apiproxy`）暴露视图与追加；`write` 接受交互打点与整段区间（旧历史的迁移会话）。这对 RPC 刻意不进受限的 `PRIVILEGED_METHODS`：交互打点就是局域网客户端自己产生的输入数据，不携带别的内容，把它们也限制到回环，恰恰会让这个功能为之存在的手机浏览器读不到共享历史。`coding-activity/updated`（revision）进入转发事件白名单，手机提交打点后，桌面的总计沿既有的 host 帧流自动重读。修订号单调递增，包内不变量断言其严格递增；零变化的追加既不写盘也不发事件；领先 Host 时钟超过十分钟的打点被拒绝（`coding-rejected`）——这是线上类型校验表达不了的唯一一条语义检查。

**开始/停止开关取消；遮罩就是空闲状态本身。** 记录是无条件的——任何交互都是打点——所以这一行没有开关：显示进行中/休息中、在场时区间计时的跳字读数、今日总计与统计弹窗。[专注门禁](2026-09-01-coding-focus-gate.md)不再是“计时停止时”催你点开始的遮罩：本页签没有输入满 `idleMinutes` 后（默认值由 10 改为 2，语义也从“自动停止计时”改为“遮罩延迟”），整个界面藏到今天编码总时长与返回提示之后，任何交互都能揭开它——打点监听挂在 window 捕获阶段，在遮罩上移动鼠标本身就重新打点。这一变化取代[无操作自动停止](2026-09-01-coding-idle-auto-stop.md)：会话不复存在，也就谈不上遗忘；两分钟桥接本身就是对被遗忘计时的修剪，且由构造保证精确。`gate`/`idleMinutes` 两个设置字段保留线上名称——含义变了，形状与消费方没变。

**浏览器只做投影，不做汇总。** 客户端控制器（ui-coding-timer 的 `activity.ts`）以节流打点记录输入（每秒一枚，挡住 pointermove 洪流），尾随三秒后批量写入（失败十五秒后重试，pagehide 时尽力一写），在转发事件上刷新，并维护一份“最近视图 + 本地待发打点”的快照。每个表面——行读数、日历格、遮罩总计——都经 `displaySpans` 派生：服务器规范区间与待发打点按同一桥接规则合并，渲染时刻尚在窗口内的活尾延伸到当前——打点在回包落地之前就点亮状态行，任何两处读数不会不一致。退役的 localStorage 历史一次性迁入共享日志（迁移瞬间仍在进行的计时计到迁移时刻），随后清除该键；损坏的旧记录原样保留。

## Alternatives considered

**保留开关，叠加基于交互的自动停止。** 被用户明确否决：声明式度量正是问题所在。也提出过“记录/暂停”开关，被否决——暂停的设备什么都不记，恰恰重建了被桥接日志要消灭的状态。

**存原始打点，读取时再算桥接。** 否决，存储与漂移双重理由：同样的信息，原始打点体积大约 90 倍；每个读者（日历、遮罩、未来表面）都必须一字不差地重演桥接规则。规范区间文档把这条规则定价一次，双方共享同一包的实现（浏览器通过 bundle 纯度门禁的明文豁免安全内联）。

**借用 settings 文档。** 否决：settings RPC 按设计仅回环（那是配置平面），局域网浏览器拿的是内存 scope——手机将看不到任何共享内容，而这正是全部诉求。而且用一个专用域加一条许可式声明也更诚实：这份日志不是配置。

**客户端折叠后整视图回写。** 否决：版本化文档上的后写覆盖会丢掉另一台设备期间写入的打点。可交换折叠下按增量追加，才能保住每台设备的贡献。

**桥接容差可配置。** 否决：历史会随每台设备当时的容差变化，日志永远无法做规范化压缩；两分钟固定写进文档格式。遮罩延迟保持可配，因为它只影响本页签的界面层。

## Consequences

时长从此度量“在场”：部署上全部设备、相邻间隔不到两分钟的打点被精确地连成区间求和；一次被遗忘的突发至多损失末尾两枚打点之间的两分钟，而不是一整个超时常数；手机与桌面读到同一份历史。发布前积累的历史向前迁移一次，退役的按浏览器 store 一并删除，窄栏也能直接打开统计弹窗（旧的已知限制消除）。代价：日志成为局域网上一个新的未认证面（理由如上，由 trusted-host 防线守住）；始终监听的打点器意味着遮罩与状态行会对偶然输入作出反应——这是“在场”的标价；文档无界增长（每次突发约 40 字节的区间，按多年预算）；离线或断网的浏览器打不过链路，打点排队到链路恢复。覆盖：包级测试钉住合并的结合/交换、严格间隔、倒置区间、迁移、零变化、未来偏移、并发追加与外部写入合并路径；apiproxy 域测试钉住缺服务、读写、拒绝映射与逐字转发；客户端测试钉住节流/写入/重试/刷新/销毁、显示投影、状态行、遮罩、日历与设置写入；组装快照驱动真实构建产物下的遮罩生命周期；浏览器 e2e 以一分钟空闲延迟驱动“遮罩—揭开—再遮罩”及关闭偏好后的重载路径。
