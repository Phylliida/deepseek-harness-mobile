# Agent Note: Coding activity as a shared interaction log — totals bridge adjacent interactions

Status: implemented

English | [中文](2026-09-06-coding-activity-shared-log.zh.md)

## Problem

The [sidebar coding-time tracker](2026-08-23-coding-time-tracker.md) measured what the user *declared* — a Start Coding press, ended by a Stop press or the [idle auto-stop](2026-09-01-coding-idle-auto-stop.md) — and kept the history in browser localStorage, so desktop and phone disagreed by construction. The request: stop measuring declarations and start measuring presence. Record every interaction (taps, clicks, pointer drift, keys, scrolls); connect any two adjacent interactions closer than two minutes into one interval; total the intervals — a lone interaction counts nothing but must anchor the next one. And the log must be one shared record over all devices, not per-browser state, so the phone's morning and the desktop's afternoon add up in one history.

## Decision

**Stamps fold into bridge-merged spans, and the server owns the fold.** Every browser stamps input onto `ctx.codingActivity` (`dsh-coding-activity`, new package under `packages/coding/`), an append-only document at `$DSH_HOME/coding-activity.json` persisting canonical *spans*: maximal runs of stamps whose adjacent gaps stay strictly under `CODING_ACTIVITY_BRIDGE_MS` (120 000 ms — a format constant, not a tunable, because the fold semantics would change under every reader if it varied). The merge is one associative, commutative operation over sorted spans, so two devices writing concurrently commute regardless of arrival order, and the appending process re-reads the document inside the cross-process writer lock before folding, so two dsh processes never clobber each other. A stamp with no neighbor inside the window survives as a zero-length span: it counts no time itself but anchors a future bridge, exactly the user's example (stamps at minutes 1, 2, 5, 6, 7, 10, 11 total 1 + 2 + 1 minutes). Canonicalization keeps storage at one span per work burst rather than one record per second of input.

**The wire is two unprivileged RPCs plus a forwarded change event.** `coding.read` / `coding.write` (`dsh-host-apiproxy`) expose the view and the append; `write` accepts interaction stamps and whole spans (the legacy migration's sessions). The pair is deliberately NOT in the loopback-pinned `PRIVILEGED_METHODS`: interaction stamps are the LAN client's own incoming data and carry nothing else, so pinning them would strand exactly the phone browser the feature exists for. `coding-activity/updated` (revision) joins the forwarded-event allowlist, so a stamp posted by the phone re-reads into the desktop's totals over the existing host frame stream. Revisions are monotonic, and the package invariant asserts their strict increase. The provider emits nothing on a no-op append, and a stamp more than ten minutes ahead of the Host clock rejects (`coding-rejected`) — the one semantic check wire validation cannot express.

**The Start/Stop toggle dies; the cover becomes the idle state.** Recording is unconditional — any interaction is a stamp — so the row has no toggle: it shows Active/Idle, a ticking elapsed readout while the live tail bridges to now, today's total, and the stats modal. The [focus gate](2026-09-01-coding-focus-gate.md) is no longer a stopped-timer cover demanding a Start press: after `idleMinutes` without input in the tab (default changed 10 → 2, now the *cover delay* rather than an auto-stop timeout), the whole UI hides behind today's total and the return hint, and ANY interaction lifts it — the recorder listens at window capture, so a pointer move over the cover itself restamps. This supersedes the [idle auto-stop](2026-09-01-coding-idle-auto-stop.md): sessions no longer exist to be forgotten, and the two-minute bridge IS the forgotten-timer trim, exact by construction. The `gate`/`idleMinutes` settings fields keep their wire names — meanings changed, shapes and consumers did not.

**The browser projects, it does not total.** The client controller (ui-coding-timer's `activity.ts`) stamps throttled input (one stamp per second keeps pointermove floods off the wire), flushes batches after a three-second trailing delay (retry after fifteen on failure, best-effort on pagehide), refreshes on the forwarded event, and holds a snapshot of the last view plus locally pending stamps. Every surface — row readout, calendar cells, cover total — derives through `displaySpans`: canonical merge of server spans plus pending stamps, with the tail extended to the render instant while now sits inside its window, so a stamp lights the row before its round-trip lands and no two surfaces can disagree. The retired localStorage history migrates once into the shared log (a running timer counts up to the migration instant), then the key is cleared; a malformed legacy entry is left alone.

## Alternatives considered

**Keep the toggle, add interaction-based auto-stop.** Rejected by the user's explicit direction: a declaration-based measure is what was wrong. A record/pause toggle was offered and declined — paused devices logging nothing recreates the very state the bridged log exists to erase.

**Store raw stamps; compute bridging at read time.** Rejected on storage and on drift: raw stamps grow 90× faster for the same information, and every reader (calendar, gate, future surfaces) would need to reproduce the bridge rule identically. The canonical span document prices the rule once, in one package both sides import (the browser inline-safely, through the bundle purity gate's documented allowance).

**Ride the settings document.** Rejected: settings RPCs are loopback-pinned by design (the configuration plane), so a LAN browser gets a memory scope — the phone would see nothing shared, which was the entire ask. A purpose domain with a permissive stance is also more honest: the log is not configuration.

**Fold at the client and write whole views.** Rejected: last-write-wins on a revisioned document loses another device's interim stamps. Appending deltas into a commutative fold keeps every device's contribution.

**Configurable bridge tolerance.** Rejected: history would change under whichever tolerance a device happened to hold, so the log could never be compacted canonically; two minutes is fixed in the document format. The cover delay stays user-tunable because it only affects this tab's chrome.

## Consequences

Totals now measure presence, exactly connecting sub-two-minute interactions across every device on the deployment; a forgotten burst costs at most the two minutes between the last two interactions rather than a timeout's full term; and the phone and desktop read one history. The pre-release history migrates forward once, the retired per-browser store is gone, and the rail now opens the stats modal directly (the old known limitation). Costs: the log is new unauthenticated-in-LAN surface (justified above, fenced by trusted-host); an always-listening recorder means the cover and row react to incidental input — the price of "presence"; the document grows unbounded (one ~40-byte span per work burst, budgeted for years); browsers off the LAN or loopback simply cannot beat the wire, and their stamps queue until it heals. Coverage: package specs pin merge associativity/commutativity, strict-gap, inverted-span, migration, no-op, future-skew, concurrent-append, and external-write merge paths; the apiproxy domain spec pins absent-service, read/write, refusal mapping, and verbatim forwarding; client specs pin throttle/flush/retry/refresh/dispose, display projection, row, cover, calendar, and settings writes; the assembled snapshot drives the cover lifecycle through the real built bundles; the browser e2e seeds a one-minute idle delay and drives cover-lift-cover plus the disabled-preference reload.
