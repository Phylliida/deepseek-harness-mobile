# Agent Note：编码闲置自动停止——被遗忘的计时器停在最后一次活动

状态：已实现

[English](2026-09-01-coding-idle-auto-stop.md) | 中文

## 问题

[专注门禁](2026-09-01-coding-focus-gate.md)让停止状态有了看守，但计时状态仍依赖用户记得按停止。从计时中的会话走开，整段缺席都被计入：总时长虚增，追踪器赖以存在的过载信号随之失真。诉求：十分钟没有点按、触摸滚动或鼠标移动后，计时器应自行停止。

## 决策

本笔记扩展[侧边栏编码时长追踪器](2026-08-23-coding-time-tracker.md)与专注门禁笔记；store、门禁与日历的决策不变。

**自动停止修剪到最后一次活动，而不是触发时刻。** 闲置超时触发时，store 的停止以最后一次活动的时间戳执行，把会话结束时间记在最后一次观察到的输入。被遗忘一整个午饭时间的计时器不会计入用户实际停止交互之后的任何时长；被休眠的手机或后台标签页节流推迟的触发也由同一修剪保持精确——唤醒路径不需要任何特判。store 既有的“结束不早于开始”钳制已覆盖零时长边界，因此 store 声明本身未动。

**监视是挂在门禁遮罩上的组件内部 hook，仅在计时中武装。** `useIdleAutoStop(running, idleMinutes, stop)` 在 window 上监听 `pointerdown`/`pointermove`/`touchstart`/`touchmove`/`keydown`/`wheel`/`scroll`（capture，因为 scroll 不冒泡；全部 passive），并以一秒重打戳节流抵御 pointermove 洪峰。它住在 CodingGate，因为 `shell.overlay` 位置在应用整个生命周期内都挂载，与侧边栏几何无关，而自动停止正是让该遮罩回归的机制。停止状态下没有任何监听器和定时器。键盘输入计入活动——尽管诉求只提到点按、滚动和鼠标移动：编码多半是打字，漏掉 `keydown` 会在一段打字进行中把计时器停掉。

**超时是 Host 用户设置里的第二个字段，而不是常量。** `idleMinutes`（模式默认 10，界限 1–480 分钟）与 `gate` 同居 `coding-timer` 命名空间，沿用门禁笔记的设置通道理由（cordis.yml 没有到达浏览器插件的通道；Host 存储让桌面与手机保持一致）。scope 的解码为每个字段独立补缺，因此在闲置字段出现之前写入的段落仍可解码，每份已存文档继续工作。统计弹窗在门禁开关旁新增自动停止行，设置面板经 `clampIdleMinutes` 解析自由键入的值，线上因此绝不会携带 Host 模式会拒绝的值。门禁面板相应更名为 `CodingTimerSettingsFace`。

## 曾考虑的替代方案

**停在触发时刻（会话结束 = 当前时间）。** 否决：该特性为被遗忘场景而生，以当前时间结束会在每次走开时悄悄计入多达整个超时的时长——恰是用户想要消除的虚增。

**固定的十分钟常量。** 依“插件不写死可调项”规则否决：为门禁而建的设置通道本就从 GUI 可达地承载每用户偏好，在同一命名空间加一个字段，比论证“为何唯独这个超时不可修改”更便宜。

**在 apply 层、store 旁的监视器。** 否决：插槽注册把 store 句柄交给框架，活动实例由框架持有，apply 层的监视只能自建实例——同一持久化键下的两个实例会经 localStorage 互相污染。组件内部行为效果也是本技术栈存放 window 监听的既定居所（scroll、拖拽、keydown 均有先例）。

## 后果

计时中的会话被丢下会自行停止，遮罩回归并显示修剪后的总时长；默认十分钟的世界无需任何设置，此改动之前写入的持久化历史不受影响。无输入的会话中段停顿（阅读、思考）是已知的误判，已与“偏好仅限回环”的告诫一起记录在包 README 的已知限制。覆盖：props-direct 的 jsdom 规格钉住触发、活动重臂、节流、修剪到最后活动、自定义超时与停止惰性各路径；装配快照泳道用启动后安装的假时钟经真实构建产物驱动同一弧线；接线规格断言闲置写入带钳制地走过 scope。浏览器 e2e 泳道未新增用例（其组合启动失败先于本改动存在）；装配快照即为可执行钉板。
