# Agent Note: Coding activity bridges gaps under ten minutes

Status: implemented

[English](2026-10-12-coding-activity-ten-minute-bridge.md) | 中文

## 问题

[共享编码活动日志](2026-09-06-coding-activity-shared-log.md)只在相邻交互间隔小于两分钟时才把它们连起来。读代码、思考、手机上稀疏的点按经常留下更长的停顿,于是真实的工作被记成孤立的零长打点:2:34、2:43、2:52、3:22、3:25、3:29 的打点合计为零。预期规则是间隔小于十分钟就合并、更长的间隔才切分,同一组打点应合计 18 + 7 分钟。同一次反馈还暴露出两个让追踪器看起来卡住的浏览器缺陷:任何一段空闲之后侧边栏行一直停在“休息中”;长时间遮罩之后,空闲遮罩会迟迟才再次出现。

## 决策

**`CODING_ACTIVITY_BRIDGE_MS` 为 600 000 毫秒。** 桥接仍是 Host 折叠与浏览器投影共用的固定格式常量;比较仍是严格小于,恰好十分钟的间隔会切分。不存在也不需要迁移:在两分钟桥接下规范化的区间,下次折叠时的合并结果与其原始打点在十分钟桥接下的结果完全相同——存储区间内部的每个间隔都已小于更宽的桥接,存储区间之间的每个间隔都是真实的打点间隔。下次写入之前,浏览器的 `displaySpans` 会对 Host 返回的内容重新合并,所以首次读取时总计就是正确的。

**空闲界面在活动变化时重新读取时钟。** 侧边栏行只在在场时跳秒,所以它的 `now` 停在最后一次跳秒;在那之后打下的新尾部永远满足不了 `now >= tail.end`,该行便一直停在“休息中”,日界线也被冻结。现在空闲时每次活动快照变化都会刷新 `now`。空闲遮罩按 `boundary - now` 设定超时,而 `now` 停在上一次触发时刻,所以长时间遮罩之后下一次遮罩会晚到整段遮罩时长;现在改为从 `Date.now()` 计算。

## 备选方案

**可配置的桥接宽度。** 否决,理由同共享日志的 Agent Note:持有不同容差的设备会把同一份历史折叠成不同结果。放宽常量没有损失;收窄无法拆开已存储的区间,所以按设备配置会让历史取决于写入顺序。

**把空闲遮罩延迟也提高到十分钟。** 未采用:遮罩是独立的、用户可调的偏好,只影响本页签的界面层。现在遮罩可能在区间仍处于在场状态时出现,其总计包含延伸到渲染时刻的暂定尾部。

**让侧边栏时钟始终每秒跳动。** 否决:空闲行的读数只在快照变化时才会变化,在每个空闲页签上持续重渲染,得不到活动变化时刷新所得不到的任何东西。

## 影响

小于十分钟的停顿计入编码时长,现有日志在下次写入时原地放宽。在场尾部现在会延伸到最后一次输入后最多十分钟,所以停顿期间“进行中”读数与今日总计会继续增长,停顿满十分钟时再回落。跨过午夜仍保持打开的空闲页签,在下一次交互或远端写入之前显示前一天的总计。覆盖:`document.spec.ts` 固定 18 + 7 的例子与严格边界,状态行与遮罩的 spec 固定长时间空闲后的恢复,组装后的 `coding-gate.snapshot.ts` 在揭开与再次遮罩之前先保持遮罩一小时;该快照现在在交互之前安装假计时器,并等待计时器自己的统计按钮。
