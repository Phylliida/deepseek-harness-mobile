# Agent Note: 专注门禁——停止计时时遮住整个界面

Status: implemented

[English](2026-09-01-coding-focus-gate.md) | 中文

## Problem

编码计时器只有记得按开始才有用。作为侧边栏里一个可选控件，用户会忘记按“开始编码”；而另一种相反的失败是——因为没有任何东西打断心流——工作远超健康的时长。诉求是：让“停止”成为被守护的状态。没有编码会话时，整个 GUI 应当隐藏在一个“开始编码”按钮之后；开始计时恢复正常界面，停止计时重新遮住。

## Decision

本笔记扩展[侧边栏编码时长追踪器](2026-08-23-coding-time-tracker.md)，其中关于 store、控件行与时长汇总的决策保持不变。

**门禁是一个 `shell.overlay` 注册项，而不是改动 shell。** `ui-coding-timer` 注册第二个条目 `CodingGate`，进入布局声明的 `shell.overlay` 列表位置——一个全框不透明遮罩，渲染今天已编码的总时长和“开始编码”按钮。开始计时翻转共享持久化 store 的 `activeSince`，这正是揭开遮罩的机制；下层应用从不卸载，视图状态不丢，停止时遮罩只是再次渲染。该位置的点击穿透契约增加一条成文的例外：这个注册项是故意遮挡的（ui-layout 的 SlotMap JSDoc 有记录）。两处注册共享同一个 store 句柄——受支持的多注册共享方式——控件行与门禁永不失配。

**偏好存于 Host 用户设置文档，不在 cordis.yml，也不在 localStorage。** 节点半边注册 `coding-timer` 设置命名空间，其中门禁字段为布尔、模式默认 `true`；浏览器半边经 `ctx.settingsScope` 绑定，并把同一份 inject 面（`CodingTimerSettingsFace`）交给两个组件：scope 本身作为 `hooks.gate` 源，外加各写入回调。关闭入口是遮罩上的“保持界面常显”链接和统计弹窗底部的开关行。Host 侧存储意味着指向同一部署的每个回环浏览器——桌面和手机——遵守同一选择；Web e2e 泳道也得以在脚手架的一处统一播种 `gate: false`（场景用 `codingGateOn: true` 重新打开），而不是在每个用例里播种浏览器存储。

**两处刻意的状态不对称。** 首次设置读取进行中时门禁不渲染——可能消失的遮罩比迟到的遮罩更糟，已关闭的门禁绝不能闪出。scope 处于内存模式时（非回环浏览器；设置 RPC 仅限回环），门禁保持默认开启但隐藏关闭入口，因为一次被静默丢弃的写入看起来就是故障。

## Alternatives considered

**cordis.yml 插件配置（`gate: true`）。** 否决：客户端插件条目由启动清单创建，没有逐行配置通道，该值不经过新的线上字段就无法到达浏览器半边（要动宿主图扫描、清单解析、启动内核三个包）。用户设置通道已经存在、可在 GUI 内直接修改，且本就是主题/语言偏好的居所。

**计时器 localStorage store 里的一个标志位。** 否决其作为主要居所：引擎的持久化是整体替换，新增字段对所有门禁出现前的持久化状态读出 `undefined`（需要“缺省即开启”的特判），按浏览器存储会在用户的多台设备间分裂偏好，e2e 泳道也得在每个用例文件里播种 localStorage，而不是变更一份 Host 文档。localStorage 对历史本身仍是正确的——历史天然按浏览器隔离。

**通过在根处条件渲染来卸载 UI。** 否决：遮罩保持所有列挂载，揭开即瞬时恢复，任何状态（草稿、滚动位置、面板几何）都不会因休息一下而销毁。

## Consequences

门禁出厂开启：全新档案打开即见遮罩，这正是目的，也是现有用户最先注意到的可见行为变化。Web e2e 泳道的默认世界会关闭它，快照基线不受影响；`coding-gate.e2e.ts` 覆盖开启路径（遮罩→开始→计时行→停止→遮罩回归）与禁用偏好的重载持久。计时器包的节点半边不再为空（命名空间注册），包新增 `dsh-settings`/`schemastery` 依赖以及 ui-layout/ui-settings 的类型边。局域网浏览器得到的是没有关闭入口的门禁——与所有 Host 支撑的偏好在该处的行为一致，已记录于包 README 的已知限制。看守计时状态的闲置自动停止记录在[其专属笔记](2026-09-01-coding-idle-auto-stop.md)中。
