# Agent Note: Autobiographical compaction review fixes

Status: implemented

[English](2026-10-12-autobiographical-compaction-review-fixes.md) | 中文

## 问题

对[自传式后端](../feature/2026-03-02-autobiographical-compaction-backend.md)的一次只读审查，经针对真实库的探测确认，发现了与 `@animalabs/context-manager` 0.10.1 集成中的缺陷。最严重的一个会让某个会话的记忆形成停止，直到宿主重启。桥接层把除 `TRANSPORT` 与 `TIMEOUT` 之外的所有失败都作为空的 `abort` 响应作答，因此一次限流、服务端错误或被取消的轮次就会隔离该分块。随后库在每次编译时都把这个分块放回队首，而引擎每轮只有一个 tick，它会在不发出调用的情况下消耗在这个分块上，从此不再形成任何记忆。其他缺陷会让记忆内容从表层丢失：后一次折叠可能替换掉前一条回忆的节点；长度超过两倍分块目标的实时消息会被分片为存储行，而引擎只映射了其中一部分；三层深的种子金字塔会两次引用其叶子，并把子节点链接到错误的父节点。

## 决策

**桥接层按 membrane 的 `complete()` 的方式报告失败。** 取消，或已路由提供方的重试策略会重试的错误码（`ctx.llm.providerRetryPolicy`，在运行时打开时读取），会以可重试的 `MembraneError` 抛出。库将其视为暂时性失败：分块或合并保留在队列中，不计入尝试次数。其他任何失败仍以空的 `abort` 响应作答，因为库对抛出的第一次 L1 调用会不加记账地重新抛出，确定性失败就会永远占据队首；不可用的回答则会走它有界的隔离流程。在下一条用户消息时释放合并隔离的逻辑已删除：取消不再进入隔离，而进入隔离的是重试只会重复的结论。为看到传输失败的 tick 解除隔离的逻辑，现在覆盖所有可重试失败。桥接层还把完整的提示——包括缓存读写——报告为该调用的输入。

**一个 tick 会越过不调用模型的队列项。** 当某个 tick 消耗了队列项却没有发起调用时，`driveTick` 会再 tick 一次，并在第一次调用处、或队列不再缩短时停下，因此每轮最多仍只发出一次调用。排在一个超出其轮次的调用之后的 tick，若其信号已触发则会被跳过。

**规划绝不把另一条回忆的节点从表层移走。** 位于另一条回忆节点之下的地面属于该节点，除非声明拥有该节点的全部覆盖范围；区间内部含有这类节点的声明会等待。地面已被另一个节点以相同或更粗层级覆盖的声明视为已被代表，因此折叠只会变粗，翻转的分辨率无法让两个节点来回交替。向后遍历只在区间持有其调用不在区间内的结果时才运行，取走它与该调用之间的每个节点，并在已落地的折叠节点处停止。`foldIdOf` 只从替换事件中读取回忆头，折叠节点落地的是已存储响应的正文块，而不是库的 `thinking` 块。

**实时消息不分片。** 引擎的策略重写 `chunkIngressMessage` 并返回 null，因此每个日志事件都是一行存储，与种子一直以来的写法相同。

**种子重建库所构建的金字塔。** 一条回忆的子节点是其区间内最外层的低层级回忆，按最宽优先选出，并按位置顺序引用；每个子节点的 `mergedInto` 指向其直接父节点。

**拒绝会被分类。** `actual` 在其预算之内的 `OverBudgetError` 是结构性的，不会重试；规模类拒绝只有在可达规模仍处于已路由窗口之内时才会重试。`compactNow()` 把每次拒绝报告为 `ManualCompactionError('summary')`，在折叠落地之前被取消的请求不落地任何内容，并重新抛出它自己的原因。

**回收会让运行时退役。** 其进行中与排队中的调用被取消，之后它不再写入任何行或记录。尝试编号从日志所命名的每个尝试之后继续，包括实时行；累积的用量只有在其记录持久化之后才会清除；`@animalabs/context-manager` 被固定为恰好 `0.10.1`，因为引擎读取策略的受保护状态。

## 备选方案

**无论是否可重试，所有失败都抛出。** 否决：库的 L1 路径对抛出的第一次调用会不加尝试记账地重新抛出，因此确定性失败会占据队首，以与隔离同样的方式让记忆形成停滞。

**保留每轮一个 tick，并在恢复时释放分块隔离。** 否决：这只是治标，释放规则遗漏的任何隔离仍会占据队首。

**把每个分片映射到其消息的 seq。** 否决：一次替换无法拆分一个日志事件，因此一条消息其他分片的回忆永远无法落地，而种子也必须复现库的分片才能对齐。

**完全放弃对规模类拒绝的重试。** 否决：规模类拒绝仍意味着策略达到了一个更小的布局，在已路由窗口之内落地它，正是让长会话保持可用的关键。

## 影响

记忆形成能从取消、限流与服务端错误中恢复而无需重启，被隔离的分块也不再阻塞其后的分块。确定性失败仍会让其区间退役直到重启，这是库自身的有界策略。回忆会留在表层，一段很长的粘贴会成为一个超大的分块，来自推理模型的折叠节点按其正文定价。手动 `/compact` 会报告它为何没有折叠任何内容，而不是“No compactable history yet”。库侧的约定缺陷——结构性拒绝以 `actual` 在预算之内的 `OverBudgetError` 抛出——已记录下来以便向上游报告。覆盖：`bridge.spec.ts` 固定失败分类；`engine.spec.ts` 固定可重试失败后的恢复、被取消的轮次以及越过被隔离分块；`plan.spec.ts` 固定保留节点、单向与成对安全的规划情形；`acceptance-reopen.spec.ts` 固定重建的金字塔；`index.spec.ts` 固定拒绝、取消、回收、尝试编号、用量以及不分片的消息。没有可运行的示例组合了这个后端，因此没有无密钥快照覆盖它。
